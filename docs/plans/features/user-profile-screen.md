# 機能実装方針: プロフィール画面(自分のプロフィール)

確認の種類: [確認済]=コードで確認 / [提案]=本方針の提案 / [未確定]=仕様不明・要確認(実装前に決める)

## 1. 機能の概要

- ログイン中ユーザー自身のプロフィールを表示・編集する画面(`/profile`)。Header の「プロフィール」から遷移する。
- 画面構成(image.png): 背景画像の上に中央の明るいグレーの角丸パネル。
  - タイトル「プロフィール」
  - アイコン(タイトルとユーザーネームの間・中央・緑の丸。2枚目image.png)
  - ユーザーネーム(入力欄)
  - メールアドレス(入力欄風の枠)
  - 自己紹介(複数行の枠)
  - 上部ナビ(ホーム / 投稿する / プロフィール / ログアウト)は既存 Header を流用。

## 2. 実装方針(比較と推奨)

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A(推奨)** | 既存 `app/profile/page.tsx` を改修。メール表示を追加し、画像のパネルUIに作り替える。DB変更なし | 既存の取得・保存・エラー処理を活用。過剰でない | 特になし |
| B | メールを `profiles.email` にコピー保存 | 取得が1クエリ | 二重管理・他ユーザーに公開される恐れ(REQUIREMENTS §9.4 違反リスク)。過剰 |
| C | サーバーコンポーネント化/Server Action | サーバー側検証 | 既存に前例なし、過剰 |

**推奨は A。** メールは Auth から都度取得し DB には保存しない。

## 3. 具体的な設計・実装方法

### 3.1 画面構造([提案]、BEM風・`DESIGN.md` §9.2 準拠)

```
section.profile-card
  h1.profile-card__title          プロフィール
  div.profile-card__icon          色付きの丸(style.backgroundColor = getUserColor(user.id))
  div.profile-card__field
    label                         ユーザーネーム
    input#username                (編集可・maxLength 30)
  div.profile-card__field
    label                         メールアドレス
    input[readOnly]               (user.email。編集不可)
  div.profile-card__field
    label                         自己紹介
    textarea#bio                  (編集可・maxLength 200)
  div.profile-card__footer        (右寄せ)
    button.profile-card__save     保存する(パネル右下)
  p.profile-card__message         成功/エラー(必要時のみ)
```

- 既存の「現在のプロフィール」表示ブロックと `<hr>`、「投稿一覧へ戻る」リンクは、画像にないため削除する(Header で遷移可能)。
- アイコン: 画像の緑は目印で、色は `getUserColor(user.id)`(ユーザーごとに固定色)とする。画像アップロードは範囲外。`user.id` は `auth.getUser()` の値を使用。未ログイン時は非表示。
- 保存ボタンはパネル右下(`.profile-card__footer` を `justify-content: flex-end`)。
- 状態(読み込み中/未ログイン)は `.profile-card--state` 的に同パネル内の中央表示とする。

### 3.2 ロジック(既存を最大限維持)

- 取得: `auth.getUser()` → `user.email` を state に保持 → `profiles` を `user_id` で `maybeSingle()`。プロフィール行がなければ空欄表示(初回は保存で作成)。
- 保存: 既存の `upsert(..., { onConflict: "user_id" })` をそのまま使用。`user_id` は必ず `auth.getUser()` の値を使い、クライアント入力を信用しない。
- 検証: ユーザー名必須(trim)・30文字、自己紹介200文字(`maxLength` + 保存時 trim)。
- エラー: `23505` は「そのユーザー名は既に使われています」(既存文言を維持)、その他は汎用メッセージ(内部情報は出さない)。
- 未ログイン時: 既存どおりメッセージ表示。ログインページへのリンクを添える([提案])。

### 3.3 スタイル(`app/globals.css` に `.profile-card*` を追加)

- パネル: 幅 約420px・中央寄せ・角丸(約16px)・背景 `#d9d9d9`、内側余白あり。画像ではタイトルは中央、ラベルは左寄せ。
- アイコン: 直径 約48px(画像比)の丸、タイトル下で中央寄せ。既存 `.chat-message__avatar` は共通化せず `.profile-card__icon` を新設(サイズが異なる)。
- 入力欄: **読みやすい配色(確定)**。パネル(#d9d9d9)上で白〜明るい背景+濃い文字(例: 背景 `#fff`、文字 `#1e293b`、細い枠線、フォーカス時に枠色強調)。画像の濃灰は使わない。
- メール欄は `readOnly` を視覚的にも区別(例: 淡い背景)。
- `.app-main` のスクロール挙動、Header、背景は変更しない。
- `@media (max-width: 600px)` でパネルを画面幅に収める。

## 5. データベースへの変更

**なし。** `profiles` は現状のまま。メールは `auth.users` から取得し、`profiles` へ複製しない。
RLS は REQUIREMENTS §9.2 の基本方針(SELECT: 認証ユーザー / INSERT・UPDATE: 本人)が実設定で満たされているか、Supabase 側で照合する([未確認])。

## 6. 処理フロー

1. `/profile` 表示 → `auth.getUser()`
2. 未ログイン → 「ログインしてください」を表示して終了
3. ログイン済み → メールを state へ、`profiles` を取得して username/bio を初期値に設定
4. ユーザーが username/bio を編集 → 「保存する」
5. 再度 `auth.getUser()` で本人確認 → 検証(必須・文字数)
6. `upsert` → 成功: 「保存しました」/ 重複: 重複エラー / その他: 汎用エラー
7. 保存ボタンは処理中 `disabled`

## 7. 実装後の確認・テスト項目

- ログイン済みで `/profile` を開くと、ユーザー名・メール・自己紹介が表示される。
- プロフィール未作成ユーザーでも空欄で表示され、保存で作成される。
- アイコンがタイトルとユーザーネームの間に中央表示され、色がチャットのアイコンと一致する。
- 保存ボタンがパネル右下にある。
- メール欄は編集できない。メールが他ユーザー向け画面(`/profile/[userId]`、ホーム、投稿詳細)に出ていない。
- ユーザー名の空欄・31文字・重複でエラー、自己紹介201文字が入力できない。
- 保存後リロードしても内容が保持される。他ユーザーのプロフィールを更新できない(RLS)。
- 未ログインで開いた場合の表示。
- 画像と見比べたレイアウト(中央パネル・ラベル位置)、スマホ幅(375px)、Header・スクロール・他画面への影響なし。
- `npm run lint` / `npm run build` が通る。
